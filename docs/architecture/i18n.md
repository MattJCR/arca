# Internacionalización (i18n)

El proyecto deberá diseñarse desde el inicio para facilitar su localización a múltiples idiomas.

Principios:

- Ningún texto visible para el usuario deberá codificarse directamente en el código fuente.
- Todos los mensajes deberán obtenerse mediante un sistema de internacionalización (i18n) o equivalente.
- Las traducciones deberán mantenerse separadas de la lógica de negocio.
- El idioma por defecto no deberá condicionar la arquitectura.
- El cambio de idioma deberá requerir únicamente sustituir los recursos de traducción.
- Las claves de traducción deberán ser estables, descriptivas e independientes del texto mostrado.

Ejemplo:

```text
ui.menu.start
battle.capture.success
error.invalid_save
planner.objective.completed
```

En lugar de:

```text
"Iniciar partida"
"Pokémon capturado"
"Error al guardar"
```

La internacionalización deberá contemplarse desde el inicio del proyecto, incluso aunque inicialmente solo exista un idioma disponible.
